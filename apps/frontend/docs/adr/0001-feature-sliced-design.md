# Feature-Sliced Design для фронтенда

Приложение выросло из одного экрана, и плоская раскладка `components/` начала смешивать секции лендинга, доменные сущности и UI-кит. Решили разложить `apps/frontend/src` по FSD: слои `app → pages → widgets → features → entities → shared`, у каждого слайса публичный API через `index.ts`, импорты — только вниз.

Рассматривали плоскую структуру `components/` + `pages/` и разбиение по фичам без слоёв. Первая не даёт общей оси зависимостей, вторая — тоже, но ещё и прячет переиспользуемые сущности внутри фич. FSD дороже по числу файлов, зато фиксирует направление зависимостей и место для нового кода.

Последствия: больше `index.ts`; глубокие импорты и импорты вверх запрещены и проверяются тестом `src/__tests__/architecture.spec.ts`; контент живёт в `model` своего слайса, общие UI и конфиг — в `shared`.
