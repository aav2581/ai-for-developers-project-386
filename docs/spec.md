# Спека «Друга на час»

> Это зеркало issue [#7](https://github.com/aav2581/ai-for-developers-project-386/issues/7).
> Источник правды — это issue. При появлении расхождений правьте
> в issue и обновляйте этот файл в одном PR.

**Формы API** живут в `api/contract.tsp` и генерируются в
`api/openapi.yaml` и `apps/backend/src/generated/*.json`. Любой
пример тела запроса или ответа в этой спеке — иллюстративный;
истина — в OpenAPI-схеме. Версии меняются в TypeSpec-контракте,
а не здесь.

## 1. Проблема

Гость приходит на лендинг «Друг на час» и хочет записаться на час к
Ваньку. Сейчас CTA ведёт на `/book`, где можно выбрать формат, но
дальше — заглушка: нет календаря, свободного времени, подтверждения
и списка записей. Занятость должна переживать перезапуск бэкенда.

## 2. Решение

Полный вертикальный сценарий: выбор формата, календарь вечеров
с 18:00 до 02:00, часовые слоты со статусами и ёмкостью,
подтверждение с именем и email, экран успеха, раздел «Предстоящие
события». Хранилище — SQLite, переживает перезапуск бэкенда.

## 3. Доменные правила

- **Вечер** — блок 18:00–02:00 в Europe/Moscow. 8 часовых слотов:
  18:00–19:00, 19:00–20:00, …, 23:00–00:00, 00:00–01:00, 01:00–02:00.
  Слоты 00:00 и 01:00 относятся к предыдущему вечеру по
  `eveningDate`, но фактическая дата `startsAt` — следующая.

- **Идентификатор слота** — `YYYY-MM-DD-HH:mm` по фактической дате
  и времени начала в Europe/Moscow. У слота также есть
  `eveningDate` — дата вечера, к которому он относится.

- **Сетка** — все семь дней, без выходных; 8 слотов ровно по 60 минут.

- **Время** — Europe/Moscow. Без перехода на летнее время. Сервер
  считает «сейчас» в этом поясе.

- **Горизонт** — вечера от сегодняшней даты до +30 дней включительно.
  Слот доступен, только если его начало строго позже текущего момента
  и не выходит за горизонт.

- **Ёмкость** — `online = 1`, `offline = 1`, `group = 4` (места).

- **Формат фиксирует первая запись.** Пока на час нет записей, гость
  выбирает любой формат. После первой записи час получает её формат
  и ёмкость; запись другого формата отклоняется как недоступная.

- **Место в группе** — номер от 0 до 3. Уникальность обеспечивается
  парой «слот + место».

- **Повторная запись** одного email на тот же час отклоняется, даже
  если места ещё есть.

- **Оффлайн** требует людное место из фиксированного списка. **Онлайн**
  и **групповой** место запрещено.

- **Гость** — имя (1–80 символов после trim) и email (нормализуется
  в нижний регистр). Полный email не возвращается ни одним
  GET-ответом: только маска вида `u***@example.com`.

- **Ссылка на онлайн-встречу** не создаётся автоматически; Ванёк
  присылает её вручную.

## 4. Хранилище

- **SQLite через `node:sqlite`**, один файл. Путь: `DB_PATH` env,
  по умолчанию `data/app.db`. Каталог создаётся при старте.

- **Одна таблица `bookings`** с полями из `api/contract.tsp`:
  `id` (UUID), `slot_id`, `evening_date`, `format`, `place`, `guest_name`,
  `guest_email` (маска хранится в `guest_email`, нормализованную
  копию держим в `guest_email_normalized`), `venue_id` (nullable),
  `starts_at` (UTC ms), `created_at` (UTC ms).

- **Ограничения**: уникальность пары `(slot_id, place)` и
  `(slot_id, guest_email_normalized)`.

- **Миграция** — идемпотентная: `CREATE TABLE IF NOT EXISTS` и
  `CREATE UNIQUE INDEX IF NOT EXISTS`. Версия схемы (`user_version`)
  и миграции — TODO после релиза вертикальных tracer-bullet-тикетов.

- **Тесты** ходят через `:memory:` SQLite. Каталог данных
  в `compose.yaml` подключён как том.

- **Сид-данных нет**: занятость появляется только из реальных записей.

## 5. API

Формат ошибок единый:

```json
{ "error": { "code": "slot_unavailable", "message": "Этот час уже занят" } }
```

Коды — `validation_error`, `slot_unavailable`, `already_booked`,
`unknown_venue`, `not_found` (см. `ApiErrorBody` в OpenAPI).

- `GET /health` — без изменений, `{ "status": "ok" }`.

- `GET /api/venues` — список людных мест. Тело ответа:
  `VenuesResponse` (`api/openapi.yaml#/components/schemas/VenuesResponse`).

- `GET /api/evenings` — диапазон не больше 31 дня; даты вне горизонта
  отсекаются. `EveningsResponse` со списком `Evening`, каждый
  содержит 8 слотов с полями `Slot` (`available` — финальный ответ
  сервера с учётом «сейчас», горизонта, занятости и формата).
  У вечера `availableSlots` — для отметок в календаре.

- `POST /api/bookings` — тело `BookingRequest`. Ответ `201` —
  `BookingCreatedResponse` с записью `BookingResponse` (с маской
  email). Ошибки:
    - `400 validation_error` — поля, формат, диапазон;
    - `404 unknown_venue` — venueId не из фиксированного списка;
    - `409 already_booked` — повторный email на этот слот;
    - `409 slot_unavailable` — прошлое, вне горизонта, мест нет,
      формат зафиксирован другой записью.

- `GET /api/bookings/upcoming` — только будущие записи по
  возрастанию `startsAt`. В каждой записи маскированный email и
  `createdAt`.

Полные схемы форм — в `api/openapi.yaml` (генерируется из
`api/contract.tsp`). Дополнительные доменные типы живут рядом
с серверным кодом в `apps/backend/src/server/types.ts`.

## 6. Frontend

- Один маршрут `/book` с шагами: `формат → вечер и час →
  подтверждение → успех`. Предвыбор формата из query `?format=`.

- Шаг расписания: календарь месяца с числом свободных часов
  в вечере и панель «Статус слотов» на 8 часов. Прошедшие
  и недоступные часы некликабельны и объяснены.

- Шаг подтверждения: сводка (формат, дата вечера, час,
  людное место для оффлайна), поля имени и email.

- `/events` — будущие записи по возрастанию времени, имя,
  маскированный email, подпись часа, `createdAt`;
  состояния загрузки, ошибки с повтором, пустое состояние.

- Шапка получает ссылку «Предстоящие события».

- Лендинг: CTA «Записаться на час» ведёт в `/book`,
  «Хочу в группу» — в `/book?format=group`.

- Минимальный FSD: `app → pages → entities → shared`. Slise SDK
  живёт в `apps/frontend/src/shared/api/sdk` (генерируется из
  `api/openapi.yaml`), публичный API слайса — в
  `apps/frontend/src/shared/api/index.ts`.

- Вёрстка адаптивная от 360 px, элементы доступны с клавиатуры,
  ошибки объявляются через `aria-live`.

## 7. Тесты

**Backend и Frontend — один шов каждый** (см. `tdd` skill).

### Backend
HTTP-шов: `buildApp({ dbPath, now })` + `app.inject(...)`. На
in-memory SQLite проверяем:
- 8 слотов вечера + перенос ночных часов на следующий день;
- «сейчас» и горизонт 30 дней;
- ёмкость форматов 1/1/4 и фиксация формата первой записью;
- людные места для оффлайна; запрет `venueId` для online/group;
- валидация имени (1–80 после trim) и email (формат + lower);
- повторный email → `409 already_booked`;
- конкурентные POST на один слот → ровно один `201`, остальные `409`;
- маскировка email в ответах;
- сортировка и фильтр «будущее» в `/events`.

`now` — фейк-таймер, часовой пояс Europe/Moscow.

### Frontend
Шов — страницы: `/book` и `/events`. Сеть подменяется на уровне
`fetch`, проверяем шаги, предвыбор формата из query, сброс
выбора при смене формата, статусы и остаток мест, недоступные
часы, выбор людного места, валидация полей, тело запроса,
экран успеха, маску в событиях, пустое состояние и ошибку
с повтором.

### Acceptance-чеклист
В issue #7. Он выполняется вручную: e2e в браузере в этой
версии нет.
